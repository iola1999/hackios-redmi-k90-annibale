# v0.2.2 发布记录（2026-11-22）

## 1. 范围

本版继续使用 iOS 26.6.2（23G90）与 XNU 12377，从三个仓库的日常分支发布：顶层 `62d0939`、内核 `aa069aef`、用户态 `491fec6`。相对 `v0.2.1` 的变化：

- 相机：后摄条纹（CAM-1）、预览亮度循环（U16）、前摄偏紫、后摄对焦马达（U17）、暗角校正与测光（U18）、曝光补偿与预览帧率（U20、U21），见 [11-21 真机体验问题](2026-11-21-user-test-issues.md)第 11～16 节。
- 相机取帧改为连续流，预览停帧、照片落盘与快门期间 GPU 停转的修复，见 [11-20 相机与照片](2026-11-20-camera-photo-icons.md)。
- 「地图」引起的 GPU 停转（S21）、Safari 空白页、TrollStore 图标、拍照后整屏闪烁（U14），见 [11-21 真机体验问题](2026-11-21-user-test-issues.md)第 5、6、8、9 节。
- loader 切回 Android 时同步 UFS Boot LUN（内核 `c755e776`），iOS 请求关机与重启时交给 loader 执行（内核 `6acd5c59`）。

用户侧变化：分区、系统盘和数据盘不变，从 `v0.2.0`、`v0.2.1` 升级只需重新合成并刷入 `boot-ios.img`，按[开发指南 §11](../development.md#11-版本号)升修订号。

## 2. 构建与发布校验

发布包按 [Release 执行清单](../plan/release-checklist.md)在新克隆里构建，日志在 Git 忽略的发布克隆 `out/` 下。

- 内核：新克隆的内核与测试机上验证过的 `12377-lens` 有 16 字节不同，位置是 LC_UUID。日常构建按 [k90auto 说明](../../tools/k90auto/README.md)每次换 `KERNEL_UUID`，发布构建用 `xnu26/build-macos.sh` 的默认值；把 `12377-lens` 的 LC_UUID 改成默认值后，SHA-256 与发布内核相同。
- loader：`build-id` 为 `6acd5c59`（最后一个改动 `xnuloader/` 的提交）。
- 用时：内核全量构建 192 秒（`v0.2.1` 为 74 秒），Mesa 68 秒，打包 7 秒，三个 `apfs-tool` 450 秒，其中大部分是 `ubuntu:24.04` 容器安装软件包。
- `apfs-tool`：三个程序与 `v0.2.1` 发布记录的 SHA-256 相同；macOS 版含 arm64 与 x86_64，最低 macOS 13，只依赖 `/usr/lib` 的 `libz` 与 `libSystem`，Linux 版静态链接。macOS 版另跑 `test_annfs.py` 2 轮、每轮 3,000 个对象，通过。
- 发布包：文件清单与 `v0.2.1` 相同（149 个文件）；plist 改动为 555 份、77,132 字节，与 `v0.2.1` 相同，没有需要人工确认来源的条目。
- 合成：在 macOS 上用发布包与 `v0.2.0` 发布时从测试机读出的固件执行 `assemble.py build`，两个镜像与发布记录逐字节相同。`assemble.py` 本版有改动，另在 `ubuntu:24.04`（arm64）容器里合成，输出「holds exactly the release's files」，压缩字节因 zlib 1.3 与 1.3.1 不同。

## 3. 上机验证

测试机从运行中的 iOS 退回驻留 loader，用 `reboot-lk.py` 进入 LK，`max-download-size` 为 805,306,368 字节。

| 步骤 | 结果 |
|---|---|
| loader 外壳 | 外壳与 `v0.2.1` 不同。`fastboot boot payload/loader-shell.img` 后 17 秒枚举出 `xnuloader`，`build-id` 为 `6acd5c59`，屏幕正常显示 loader 界面 |
| 刷入引导镜像 | `fastboot flash boot_a` 写入 96 MiB 用时 2.7 秒，`set_active a` 后重试次数为 7；重启后 19 秒枚举出 loader，35 秒时 `result` 变为 `running`，默认镜像自动启动 |
| iOS | `kern.osversion` 为 23G90，两个 Cryptex 以嫁接方式接入，停在锁屏；上滑解锁后主屏两页图标齐全 |
| LaunchServices 重建 | 验证前删除测试机的 `/private/var/db/.annibale-cryptex-grafted`，模拟从 `v0.2.1` 升级后的第一次开机。init 删除 2 个数据库文件，lsd 重建后用 TrollStore 安装的 4 个应用（含 TrollStore）仍在主屏；Safari 打开百度并显示图文，3 个 WebKit 进程运行 |
| 相机 | 后摄预览无条纹，亮度正常；每 300 帧用 10.2～12.6 秒。按快门后照片保存为 `IMG_0056.HEIC`。打开相机时的第一次搜索停在 391，此后插件 3 次重新搜索都停在 189～223，截图画面发虚，见第 4 节 |
| 切回 Android | 驻留 loader 空闲后执行 `fastboot -s xnuloader oem android`，25 秒后 B 槽 Android 启动完成 |

iOS 请求重启或关机时由 loader 执行的路径没有验证：iOS 里没有能从主机触发重启的命令，关机后需要按电源键开机。验证结束后，按用户要求设备留在 Android。

## 4. 发版中发现的问题

- 发布配方：`camtuning.py` 自内核 `aa069aef` 起需要传感器模块文件和模式号，`assemble.py` 仍只传调校文件，用户合成的 `camera-*.isp` 会与根盘不同。顶层 `62d0939` 修正配方后发布；检查方法写进 [Release 执行清单 §5、§9](../plan/release-checklist.md#9-历次发版遇到的问题)。
- 内核比对：日常构建与发布构建的 LC_UUID 不同，比对方法写进清单第 4 节。
- 后摄对焦：本批改用 CMCapture 的 13 个搜索位置后，相邻位置相差约 62 个镜头单位，抛物线插值后的镜头多停在 390～410（`u22a`～`u22f` 与发布验证）；改动前的逐步细扫在同一书桌场景停在 432～444，截图清晰（`lf1`、`br1`、`br2`）。另外，自动曝光收敛后亮度变化触发重新搜索，重新搜索的清晰度读数只有 0.001～0.007，提前结束在 210 附近。按用户要求先发布，记为已知问题，跟踪见[多媒体待办 M6](../backlog/multimedia.md)。
- `recover-loader.py` 第一次运行时，`oem stop` 后 `getvar result` 在 8 秒内没有应答（loader 重新枚举中），脚本报错退出；随后 loader 已处于空闲且常驻区为空，第二次运行通过。
