# 2026-11-08 Wi-Fi 状态栏灰标与 LQM 事件

状态栏 Wi-Fi 图标持续灰色，设置页同时显示满格。静态分析已定位到两个界面使用的不同信号来源，并完成一项最小内核修复及生产函数测试。真机效果尚未验证。

## 1. 两个界面的状态来源

设置页从当前网络和扫描结果读取真实 RSSI。内核 `redwood_apple80211.c` 的 `give_network()` 返回 `bss->rssi`，RSSI ioctl 也返回该值；IO80211 的当前网络转换路径使用同一数据来源。

状态栏由 `SBSystemStatusWifiDataProvider` 读取 `SBWiFiManager.signalStrengthBars`，并结合 `isPowered`、`isPrimaryInterface`、`isAssociated` 和 `isFallingBackToCellular` 计算 `wifiActive`。信号强度的原生更新链如下：

- IO80211 的事件 39 解析器要求至少 `0x1d8` 字节，byte 0 是 RSSI 有效标志，偏移 `+4` 是有符号 RSSI。
- `wifid` 通过 `__WiFiDeviceProcessRSSIEvent` 更新设备对象并生成 `SCALED_RSSI`。
- SpringBoard 的 LQM 回调消费 `SCALED_RSSI` 和原始 `RSSI`，再调用 `_updateSignalStrengthFromRawRSSI:andScaledRSSI:`。

当前网络已有真实 RSSI 时，设置页可以显示满格；状态栏还依赖 LQM 事件和 `wifiActive` 的其他条件。四轮性能 A/B 的最终主屏截图均为 Wi-Fi 灰显，回退内核、Metal 或 AIR 没有改变该现象。

## 2. 已确认的内核缺口与修复

`redwood_apple80211_event()` 原来只发送 `EVENT_LINK_CHANGED(4)`，没有发送 `EVENT_LQM_CHANGED(39)`。这使状态栏所需的原生 RSSI 更新链缺少输入。

最小修复保留现有链路事件，并在链路上升的 LINK 事件之后补发事件 39：

- 新增 472 字节的 LQM 负载，布局和长度由编译期断言检查。
- byte 0 置为有效，偏移 `+4` 写入现有 `link.rssi`，其余负载清零。
- 链路下降路径保持原行为。
- 没有修改 UI、固定信号格数或增加用户态轮询。

改动位于 `hackios-xnu-kernel/xnu/files/bsd/dev/redwood/redwood_apple80211.c`，测试位于 `hackios-xnu-kernel/tools/tests/test-redwood-apple80211-events.py`。
