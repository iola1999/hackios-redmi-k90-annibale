本文汇总 2026-11-19 阶段五、阶段六及 Batch 6（`s6a`～`s6h-r2`，最终真机内核 `12377-s6h2`）的已验证进展、设备状态、未完成事项与下次恢复步骤。各专题实现细节见[阶段五进展](2026-11-19-stage5-s21-misc9.md)与[阶段六进展](2026-11-19-stage6-modem-camera-graphics.md)。

## 1. 本批完成与真机状态

- **性能与系统调度（`PERF-1`／`PERF-2`／`PERF-3`／`PERF-5`）**：完成 `work_interval_ctl`（`6/7/8`）、`sched_perfcontrol_callbacks` v7 与 `IOGPU` 角色服务（`s6e-r1` `setGPURole` 零失败）、`locore.s` `24 MHz` 时钟快路径（`s6e-r2` 实测 `62 ns`/次）、AIR 无锁刷新与管线缓存键统一（`s6f-r1` `backboardd` `refresh_max` 降至 `833 us`），以及 APFS 数据卷 3 轮性能基线（`s6f-r2`）。
- **桌面条纹与动态闪烁清除（`s6g-r3`）**：移除 `0020` 补丁 `fd6_barrier.cc` 对 `CP_CCHE_INVALIDATE` 的屏蔽，并在 `adreno8_speed_tick()` 切档前调用 `adreno8_context_wait_idle("GPU speed")` 排空；`s6g-r3` 在 `adreno8_speed=14` 下运行 `31` 次切档，主屏 19 个图标与 Dock 毛玻璃零静态条纹、零动态闪烁、零 GPU 停转。
- **MPSS 基带、休止生命周期与 `QMI_LOC`（`s6f-r3`～`s6h-r2`）**：打通 `HYP_ASSIGN`、`SMP2P`、`SMEM GLINK IPCRTR`、`SMEM_HOST_GLOBAL` 隔离、`PAS_SHUTDOWN`、返回 loader 前静默及 `WDS`/`DMS`/`NAS`/`WMS`/`Voice`/`UIM`/`LOC` 7 项服务上线（`modem_state = 4`，`0` SMMU 故障、`0` `SMEM 421` 崩溃）；`s6h-r2` 实测 `QMI_LOC` `0x001e`/`0x001f`/`0x0020`（`rev=2`）均返回 `err=0`。
- **相机拍照链与 VBLANK 同步（`s6f-r3`～`s6h-r2`）**：落地 `align_cmcapture_compression_caps()` 消除 `-6680`，修复 `MiniM2Scaler` 顺时针 90° 旋转与原子 `fAbortGen`，实现 `-[MTLDevice newBufferWithIOSurface:]` 消除 `-73465`；`s6h-r2` 将 `cam_native_wait_vblank()` 改为等待 bit-9 `INFO_INPUT_EOF (0x200)` 后 `vblank wait timeout` 降至 `0` 次，并接入默认关闭的 `cam_wm_prefetch`。
- **麦克风 `Q6PRM` 与 `VA_MACRO` 初始化（`s6h-r1`～`s6h-r2`）**：实现 `/dev/annibale-mic` 4 槽异步 GPR 流水线与 `PRM_CMD_REQUEST_HW_RSC (0x0100100f)` 线上格式，按 `annibale-merged.dts` 启用 `VA_MACRO`（`0x07660000`）与 DMIC 引脚；`s6h-r2` `REQ LPASS CORE`、`REQ VA MCLK`、`OPEN SG_MIC`、`SET_CFG MIC_SOURCE` 与 `OPEN SG_CAPTURE` 均成功，连续两次 `record_test` 打开关闭正常。
- **设备停放状态与清理**：`s6h-r2` 结束时主屏运行 `0` GPU 停转、`0` SpringBoard 崩溃循环，随后通过 `recover-loader.py` 退回低功耗空闲 `xnuloader`（`product: xnuloader`、`result: idle`、`ramdisk-state: idle 0 0 0`、`slot-retry-count:a: 7`）。已删除 `/tmp/hyp_a.elf` 与 `/tmp/tz_a.elf` 并记录于 `out/cleanup-2026-11-19/cleanup.txt`，已注册内核、`annibale-backup/` 与实测目录保留完整。

## 3. 未完成事项与下次恢复步骤

1. **相机预览 `bus_ovf=0x1` 与照片落盘（`CAM-3`／`M6`）、`CAM-1` 256B 半块条纹**：`s6h-r2` `seq=4` 仍在 `fll=12500 exp=12468` 命中 `bus_ovf=0x1`（`consumed=0`，`path=0xe91fd8`），`DCIM/100APPLE` 仅 `.MISC`。下一步先在已上线的 `12377-s6h2` 零重编对照 `cam_wm_prefetch=1`（`CAM-1`），并测试 `cam_keep_stream=0` 与在 `cam_native_apply_exposure_regs()` 加入 OmniVision group-hold（`0x3208`），同时核查 `WM0`（`0x1790`）在 `RUP_DONE` 与 `FIFO_OVF` 同时置位时 `consumed=0` 的原因。
2. **`QMI_LOC 0x0021` 与 `DMS OFFLINE`（`P13`／`P14`）**：`s6h-r2` 已确认 `0x001e`、`0x001f`、`0x0020`（`loc_rev=2`）均成功，但 `0x0021`（`mask=0x187` 与 `0x01`）仍各收到 `err=48` 与 `err=3`，且 `DMS` 停在 `mode=3`（`dms_err=60`）、`UIM` 报 `card=2 err=3`。下一步核对 GNSS 引擎锁（`GET_ENGINE_LOCK`）、`DMS operating_mode=3` 对 MPSS CGPS 的前置限制、`QMI_LOC` 初始化顺序（`SET_OPERATION_MODE`／`GET_OPERATION_MODE`）及 `UIM` 卡槽检测状态。
3. **麦克风有声采集（`M8`）**：`s6h-r2` 在 `SET_CFG CAP_ENC`（[annibale_mic.c](../../hackios-xnu-kernel/xnu/files/bsd/dev/annibale/annibale_mic.c) 参数 `0x08001006`）返回 `0x3`（`AR_EUNSUPPORTED`），且 `mic_start()` 失败后未关闭已打开的 `SG_MIC`／`SG_CAPTURE`，致使重试循环持续收到 `0x18`（`AR_EALREADY`）、`record_test` 采样全零。下一步核对 `MOD_PCM_ENC` 支持的参数格式并补齐失败关闭清理路径；若 `VA_MACRO` DMIC0 仍无硬件信号，再核对 `tx_macro@0x06ae0000` 与各路 DMIC 通道映射。
4. **开机桌面图标／组件偶发延迟出图（`Effect A`）**：在 `s6c3`、`s6e2`、`s6g1`、`s6h-r1` 出现解锁后桌面仅渲染壁纸、Dock 胶囊、搜索栏与图标文字，图标图形与组件缺失，日志中 `SpringBoard` 停在 180 次独立 `tl: Q` 提交、`iconservicesagent` 停在 5 次提交、`chronod` 30 秒超时，同时 `SpringBoard` 主线程记录 `SBHIconServicesImageForDescriptor`／`voucher_activity_trace_v_2` 的 `mach_msg2_trap` 阻塞，待 `30` 秒后或拉起应用后恢复。`s6h-r2` 未复现；下次排查在复现轮采集全进程堆栈，定位阻塞 `SpringBoard` 与 `iconservicesagent` 的同步 XPC 对端。
