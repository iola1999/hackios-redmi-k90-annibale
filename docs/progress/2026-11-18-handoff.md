## 4. 未完成事项

按建议顺序：

1. 驻留开机的蓝牙固件下载停住（MISC-9 遗留）：`v0.2.1` 的 `boot_a` 驻留开机 7 次中 4 次停在下载开始处，拉起线程不结束，设置与控制中心卡死的风险在这类开机里仍在；k90auto 轮次 7 次全部成功。开机时 BT_EN 都是低电平，芯片状态跨重启保留已排除。先取停住时的内核线程栈，再对比 loader 两条启动路径在 BT 拉起期间的差异，见[卡死与 BT 拉起修复 §7](2026-11-18-ui-freeze-bluetoothd.md#7-驻留开机的固件下载停住发布后观察)。
2. GPU 停转（[S21](../backlog/system.md)）：打开「地图」后让定位授权弹窗保持显示即可复现（不开同步绘制的 5 次全部停转）。已排除可空未绑定槽位、LRZ 与分块渲染，逐次同步绘制时不出现。下一步在内核 SMMU 故障处理里读出 CP 的 IB1／IB2 地址并对应到 BO 与进程，再用 `ANNIBALE_SYNC_MATCHED_DRAWS` 缩小到具体绘制，过程见[相机观测与闪烁 §5](2026-11-18-camera-trace-and-perm-flicker.md#5-地图快照服务崩溃与-gpu-停转复现)。复现轮次留在 iOS 时要另外监视，`cycle.py` 只在留机前检查一次。
3. 拍照保存（CAM-3，[M6](../backlog/multimedia.md)）：找出快门后拍照结果停在相机应用回调、cameracaptured 编码节点还是 `deferredmediad`，再决定是否在 Mesa 实现双平面纹理的着色器写入。
4. 后摄半块条纹（CAM-1）：按物理地址第 8 位隔块丢失，查 CAMNOC 的地址映射与交织配置。
5. 设置「隐私与安全性」页卡死与 bluetoothd 的关系未确认，复现时取设置主线程栈。
6. 本批没有处理的待办：PERF-1／2／3／5、MISC-2～5、TOOL-7，见[后续安排](../plan/2026-11-16-followup.md)。

需要用户决定的事项：

- Espresso 在无 ANE 时自带的 CPU 回退要求内核报告运行在虚拟机里，会影响其他读取同一信息的框架，是否采用待定。
- 三个仓库的 `stash@{0}` 是否删除。
- `v0.2.1` 的 GitHub 发布说明写的是「三次开机蓝牙都正常拉起」，是否在已知问题里补上驻留开机的下载停住。
