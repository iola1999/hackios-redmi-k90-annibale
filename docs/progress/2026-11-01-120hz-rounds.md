# 120 Hz 与上游做法的真机轮次（2026-11-01）

用户在 2026-11-01 要求实施上游 hakios 里可借用的改动并上真机验证，随后反馈手势离 120 帧／秒还远、常掉到 60 以下。本文记录这一天的轮次与读数。改动来源见[上游做法](../analysis/2026-11-01-hakios-upstream-lessons.md)，开关的作用见[120 Hz 手势帧率的卡点](../analysis/2026-11-01-120hz-gesture-bottleneck.md) §7，rt2 的逐帧分析见同一文档。

## 1. 轮次

两轮都用内核 `12377-rate1` 和 `cycle.py`，基线 `kernel-12377-cmd54-bo63`。boot-arg 在 `usertrap=1 fb_flip=2 touch_poll_us=4000` 之外加表中开关，打包时 `GPU_SPEED=3`（GPU 最高 342 MHz）。手势帧率用 `gestures.py` 读。

| 轮次 | 开关 | 结果 |
|---|---|---|
| rt1 | `fb_hz=120 fb_ca_hz=120 dl_log=1` | `UIScreen.maximumFramesPerSecond` 与 `currentMode.refreshRate` 为 120，CoreAnimation 采用了 120 Hz；`restriction=0`，不需要 `HIGHRATE=1`；控制中心下拉 71.5、左滑 74.3 帧／秒（`bo63` 为 54.0、54.9）；最高 73.3 °C |
| rt2 | rt1 加 `dl_max=1`；`--hold` 保持 268 秒，期间用户手动滑动 | 左滑 80.1、右滑 70.6、控制中心下拉 68.0 帧／秒，帧间隔 p95 都在 28 ms 左右；`dl_max` 丢掉了 UIKit 进程内动画的速率请求 |

轮次目录是 `kernel-12377-rate1-rt1` 与 `kernel-12377-rate1-rt2`。

## 2. 读数

- ir3：rt1 里用了私有内存的 stage 共 11 个，都在 SpringBoard 和 iconservicesagent 里，每个 512 字节，`max_reg` 不超过 11；backboardd 没有。关掉 preamble 重编（`ANNIBALE_IR3_SPILL_RETRY=1`）因此不上真机。
- display link：rt1 的 `dl_log` 显示，iOS 26 里 UIKit 进程内动画的类名是 `UIKit.InProcessAnimationManager`（16.5 是 `UIViewInProcessAnimationManager`）。`dl_max` 的匹配表已加上这个类名，从 rt2 起生效。
- rt2 的长帧大多是 GPU 时间超过一拍，两轮 GPU 都只到 342 MHz，见[卡点分析](../analysis/2026-11-01-120hz-gesture-bottleneck.md) §1。
