# v0.2.1 发布记录（2026-11-18）

## 1. 范围

本版继续使用 iOS 26.6.2（23G90）与 XNU 12377，从三个仓库的日常分支发布：顶层 `d88f3e7`、内核 `c3507c15`、用户态 `2244410`。相对 `v0.2.0` 的变化：

- 蓝牙拉起与界面卡死修复（[卡死与 BT 拉起修复](2026-11-18-ui-freeze-bluetoothd.md)）。
- 第二阶段的亮度、存储与 panic 回溯（[后续安排 §5](../plan/2026-11-16-followup.md#5-存储nvram背光与过渡方案收敛)）。
- 第三阶段的瞬态渲染与图标修复（[11-17 瞬态渲染与图标修复](../analysis/2026-11-17-transient-render-and-icon-fixes.md)）。
- 第四阶段的相机管线（[11-17 相机管线修复](../analysis/2026-11-17-camera-pipeline-and-isp-fixes.md)）。
- loader 的单次 Fastboot 标记与连接 USB 时 15 秒的启动菜单（[后续安排 §4](../plan/2026-11-16-followup.md#4-开发与自动化工具链运行态恢复与原生-usb)）。

用户侧变化：分区、系统盘和数据盘不变，从 `v0.2.0` 升级只需重新合成并刷入 `boot-ios.img`，按[开发指南 §11](../development.md#11-版本号)升修订号。内核删除了 `ANNFS001` 数据盘支持，`v0.1.2`～`v0.1.4` 的安装先按 `v0.2.0` 的步骤迁移。

## 2. 构建与发布校验

发布包按 [Release 执行清单](../plan/release-checklist.md)在新克隆里构建，日志在 Git 忽略的发布克隆 `out/` 下。

- 内核：新克隆构建的内核与测试机上验证蓝牙修复的 `12377-bt1` 逐字节相同。
- 用时：内核全量构建 74 秒，Mesa 36 秒，打包 10 秒，三个 `apfs-tool` 134 秒，与 `v0.2.0` 相当。
- `apfs-tool`：`tools/apfs` 自 `v0.2.0` 没有改动，三个程序与 `v0.2.0` 发布记录的 SHA-256 相同；macOS 版含 arm64 与 x86_64，最低 macOS 13，只依赖 `/usr/lib` 的 `libz` 与 `libSystem`，Linux 版静态链接。macOS arm64 版另跑 `test_annfs.py` 2 轮、每轮 3,000 个对象，通过。
- 发布包：文件清单与 `v0.2.0` 相同；plist 改动由 552 份、72,060 字节变为 555 份、77,132 字节，没有需要人工确认来源的条目。
- 合成：在 macOS 上用发布包与 `v0.2.0` 发布时从测试机读出的固件（体验说明第 5 步自 `v0.2.0` 未改）执行 `assemble.py build`，两个镜像与发布记录逐字节相同。`assemble.py` 与 `localfiles.py` 没有改动，未在 Linux 容器里合成。

## 3. 上机验证

测试机从运行中的 iOS 经 `recover-loader.py` 退回驻留 loader，再用 `reboot-lk.py` 进入 LK，`max-download-size` 为 805,306,368 字节。

| 步骤 | 结果 |
|---|---|
| 刷入引导镜像 | `fastboot flash boot_a` 写入 96 MiB 用时 2.7 秒，`set_active a` 后重试次数为 7；重启后约 24 秒枚举出 loader，`build-id` 为 `ff6921e2`（最后一个改动 `xnuloader/` 的提交）；约 35 秒时 `result` 变为 `running`，默认镜像自动启动 |
| iOS | `kern.osversion` 为 23G90，`darwin_var` 以 APFS 容器挂载，SpringBoard 运行，停在锁屏（发布镜像不自动解锁） |
| 蓝牙 | 内核拉起完成（`reset: done`、`handed to bluetoothd`）；锁屏打开控制中心，长按连接模块后再长按蓝牙，弹出「正在载入…／蓝牙设置…」菜单；开机后 4 分钟内 bluetoothd 保持 pid 46，没有 watchdog 中止 |
| 背光 | 背光驱动从 NVRAM 恢复 22 nits；backboardd 随后下发 140 nits 的 `DisplayBrightnessNitsNVRAM`，驱动按种子处理并保持 22 nits |

验证结束后设备留在 iOS 锁屏。

## 4. 发版中发现的问题

在新克隆里按清单运行 `test_annfs.py` 时找不到 `apfsck`（新克隆没有编译它），改在日常工作区运行；检查方法写进 [Release 执行清单 §4、§9](../plan/release-checklist.md#9-历次发版遇到的问题)。
