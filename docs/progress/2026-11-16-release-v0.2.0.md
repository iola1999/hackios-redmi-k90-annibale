# v0.2.0 发布记录（2026-11-16）

## 1. 范围

本版继续使用 iOS 26.6.2（23G90）与 XNU 12377，从三个仓库的日常分支发布：顶层 `40a59ae`、内核 `4d570f48`、用户态 `c86af29`。相对 `v0.1.4` 的主要变化是数据盘改用 APFS（[可写 APFS](../analysis/2026-11-16-apfs-write-path.md)）、新增 `darwin_nvram` 分区（[持久化 NVRAM](../analysis/2026-11-16-persistent-nvram.md)）、引导镜像自带 AVB 页脚，以及 MiniAMFI 平台二进制判定、UFS 异步完成竞争和相机 V57 配置的修复。

用户侧变化：调整了分区并迁移数据盘，按[开发指南 §11](../development.md#11-版本号)升次版本号。

- 新装在写完系统盘后用 `annfs-to-apfs.py --format` 建 APFS 数据卷。
- `v0.1.2`～`v0.1.4` 的安装先迁移数据盘，再刷新镜像，最后拆出 `darwin_nvram`。
- 合成前多读两个相机调校文件。

## 2. 构建与发布校验

发布包按 [Release 执行清单](../plan/release-checklist.md)在新克隆里构建，日志在 Git 忽略的发布克隆 `out/` 下。

- 内核：新克隆构建的内核与测试机上验证 NVRAM 的 `12377-nvram1` 逐字节相同，LC_UUID 也相同。loader 的 `build-id` 为 `64f915ce`，与测试机上的一致。
- 用时：内核全量构建约 80 秒，Mesa 37 秒，打包 9 秒，四个 `apfs-tool` 共 148 秒（Linux 两个平台在容器里装编译器）。
- `apfs-tool`：macOS 版含 arm64 与 x86_64，最低 macOS 13，只依赖系统的 `libz` 与 `libSystem`；Linux 版静态链接。四个架构各用 `test_annfs.py` 转换 2 轮、每轮 3,000 个对象，逐对象读回与 apfsck 都通过。
- 迁移脚本：`test_annfs_to_apfs.py` 用模拟手机的 adb 跑通没有 `darwin_nvram` 的迁移、有 `darwin_nvram` 的迁移和新装 `--format`。
- 合成：在 macOS 上用发布包、按体验说明第 5 步从测试机读出的固件执行 `assemble.py build`，两个镜像与发布记录逐字节相同。在 `ubuntu:24.04`（x86_64）容器里合成，根盘文件与发布记录一致，zlib 1.3 与发布时的 1.3.1 压缩字节不同。

## 3. 上机验证

测试机从运行中的 iOS 经 `oem stop`、`reboot-bootloader` 进入 LK，`max-download-size` 为 805,306,368 字节。

| 步骤 | 结果 |
|---|---|
| 临时启动 loader 外壳 | `fastboot boot payload/loader-shell.img`（96 MiB）后约 24 秒枚举出 loader，`build-id` 为 `64f915ce`，`result` 为 `idle` |
| 读取固件 | 切到 B 槽 Android，按体验说明第 5 步原样执行；两个相机调校文件在 `/odm/lib64/camera/`，与日常工作区的副本逐字节相同 |
| 刷入引导镜像 | `fastboot flash boot_a` 写入 96 MiB 用时 2.7 秒，`set_active a` 后重试次数为 7，约 24 秒枚举出 loader，默认镜像自动启动 |
| iOS | `kern.osversion` 为 23G90，SpringBoard 运行，停在锁屏（发布镜像不自动解锁）；`/private/var` 为可写 APFS；loader 读到 bank 0 代数 11、bank 1 代数 9，选 bank 0，`nvram -p` 中的变量与上一轮相同；设置变量后写 bank 1（代数 13） |
| 背光 | 驱动以 NVRAM 里的 5972（354.468 nits）启动，随后 backboardd 下发 140 nits 的 `DisplayBrightnessNitsNVRAM`，屏幕停在 140 nits，详见[持久化 NVRAM §5](../analysis/2026-11-16-persistent-nvram.md#5-背光) |
| 硬件 CRC32 | `hw.optional.armv8_crc32 = 1`；`darwin_nvram` 16 MiB 处 `nvram-r2` 留下的 panic 记录（正文 262,057 字节），正文 CRC `ede93e71` 与头部 CRC `6bfdf0fc` 都与主机 zlib 的结果一致 |

发布镜像上没有再触发 panic：内核与 `nvram-r2`、`nvram-r3` 验证 panic 日志时的内核逐字节相同。验证结束后设备留在 iOS。

## 4. 发版中发现的问题

处理方法和以后的检查写在 [Release 执行清单 §9](../plan/release-checklist.md#9-历次发版遇到的问题)：复制输入时漏掉 `fw-camera` 链接指向的目录、新克隆的 ios 步骤找不到 IPSW、把已合入的硬件 CRC32 误判为未合入、AVB 页脚、`apfs-tool` 的可移植性、相机调校文件缺少发布配方、调校文件的手机路径写错，以及亮度结论只看了驱动启动值。
