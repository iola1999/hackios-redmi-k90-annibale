# v0.2.4 发布记录（2026-11-28）

## 1. 范围

本版继续使用 iOS 26.6.2（`23G90`，iPhone 17 `V57AP` 身份）与 XNU 12377 内核，从四个仓库对应 `v0.2.4` 提交基线发布：顶层 `ec4ba873`、内核 `adb193ad`、用户态 `93cef6d5`、`TrollStore` `5a84ac25`。相对 `v0.2.3` 的主要变化：

- 相机与多媒体：移出 `cameracaptured` VMM 伪装与清理持久化 `MobileGestalt` 缓存，恢复前后摄物理切换并设 `xnuloader` 默认 `front_cam_rotation_isp = 0` 实现默认正立；`ldob8` 改为按需单次供电并收窄 `OVX8000_LENS_STEP=32/16` 软着陆与断电停泊，见[批 18～19 记录](2026-11-28-batch18-results.md)。
- 图形、通知中心与性能：`inject_sb26.c` 恢复壁纸提交并在开机解锁期重置空闲计时器消除通知中心全黑（`near_black=0.00%`）；合入稀疏 ArgBuf、结构体填充、`air.amplification_id`、`rwa_texture_set_view_slices()` 与 `box->z` 修正及 `rw_say_write` 零休眠，点亮天气 4/4 城市卡片（`errors=0`）；落地 `/private/var/db/annibale-nircache/`、`rwa_lock` 多锁解耦、`ENG-09` `18/18` 通过、Format 94 `'l10r'`、`G8` `18/78/88`、`G30` 阶段 2（`gpu_recover=1`）与双上下文抢占，见[批 16 记录](2026-11-27-batch16-results.md)、[批 17 记录](2026-11-27-batch17-results.md)。
- 电源、存储与外设：合入 `psci_idle=1` 四核 `C4` 与 `adreno8_ifpc=1` 联合省电、`Goodix` `500 Hz / 125 Hz` 两档轮询、蓝牙 `BT_EN` `20 ms` 复位脉冲、FastRPC `apps_smmu` 非回写访问、APFS `ENOSPC` 回滚与 UFS 异步错误处理、应用原生卸载与中文字体／通知跨重启一致，见[批 14 与批 15 实测](2026-11-27-batch14-results.md)。

用户侧升级边界：分区、系统盘与数据盘结构不变。从 `v0.2.3` 升级保留全部固件与 `fw/wifi-mac.txt`，只需按[体验说明 §6、§11](../user-guide.md#6-合成引导镜像)重新合成并刷入 `boot-ios.img`；从 `v0.2.0`～`v0.2.2` 升级补采 `fw/wifi-mac.txt` 后重合成刷机；`v0.1.2`～`v0.1.4` 须先按 `v0.2.0` 与[双系统部署手册](../plan/dual-boot-setup.md)迁移 APFS 数据盘。

## 2. 构建与发布校验

发布包按 [Release 执行清单](../plan/release-checklist.md) 在独立新克隆 `../hackios-release-v0.2.4` 中全量构建。

- 内核与用时：`build-all.sh` 8 阶段全通（`ios` 13 s、`userland` 11 s、`mesa` 28 s、`package` 11 s、`kernel` 68 s、`loader` 3 s、`android` 0 s、`apfstool` 72 s）；`xnu12377-local.bin`（`21,073,816` B，`5898e7fa...`）的 `otool -l` 段布局与真机验证 `xnu12377-flipwd30.bin`（`7aff0913...`）一致。
- loader 与引导镜像：`avbtool.py info_image` 验证 `boot-a-ios.img`（`100,663,296` B / 96 MiB）含 AVB 页脚（`Original image size: 24584192 bytes`、`VBMeta offset: 24584192`、`512` B、Hash descriptor SHA-256 `1db29d26...`）。
- `apfs-tool`：`apfs-tool-Darwin` 含 `x86_64 arm64`、`minos 13.0`、仅依赖 `/usr/lib/libz.1.dylib` 与 `/usr/lib/libSystem.B.dylib`；`apfs-tool-Linux-x86_64` 与 `apfs-tool-Linux-aarch64` 为静态链接 ELF64。全 4 平台运行 `test_annfs.py --rounds 2 --objects 3000` 通过（`round 0..1 ok`）。
- 发布包清单：`build-release.py v0.2.4` 核对 `files_count: 160`、`local files by kind`: `plist: 558, copy: 13, skeleton: 1, firmware: 13, cache: 1`、`property list edits carry 77498 bytes of values`；`manifest.json` 记录 `ec4ba8730ad3339a7938d2a7410fe18a43bba18d` / `adb193ad74d666207a452f47fd19f472821e27d1` / `93cef6d57aa5c98a12bed3cc73ad006ff4464146` / `5a84ac250f8c7261bc2f49f42ebd01d19ec84132`，全包零 `/Users` 与隐私残留。
- 跨平台合成：`assemble.py build` 在 macOS 生成 `root.apfs`（`22,315,008` B，`a8dd9008...` 与发布基准逐字节一致）与 `boot-ios.img`（`100,663,296` B，`8724aa78...`）；在 `ubuntu:24.04` 容器（Python `zlib 1.3` vs `1.3.1`）生成 `root.apfs`（`a36c64ba5de401b511a8db385ac2e2ca268ba27939d93883ebb3a9386b88c532`）与 `boot-ios.img`（`3cd5cd303e65fcd027f924b78671fa68807c2d8cfb9029164eef504d3a35c9eb`），校验通过。
