# v0.2.0 后续执行批次与待办汇总（2026-11-16）

本文汇总 `v0.2.0` 发布后（顶层 `fd5b41a`、内核 `4d570f48`、用户态 `c86af29`）接续推进的待办事项与执行边界。长期候选维护在[待办目录](../backlog/README.md)，已完成阶段见[进度表](2026-10-23-tracking.md#3-已完成阶段)与 [v0.2.0 发布记录](../progress/2026-11-16-release-v0.2.0.md)。

## 1. 当前基线与搁置边界

三个仓库与 `TrollStore` 子模块工作树干净且已推送远端。测试机已枚举 `xnuloader`，运行 `v0.2.0` 发布镜像并停在 iOS 锁屏，`darwin_var` 已迁移为可写 APFS，LUN 0 已拆出 32 MiB 的 `darwin_nvram` 分区。

- 已在 `v0.1.4` 与 `v0.2.0` 合入并上机验证的项目不再重复列入本表；此前研究记录提到编译失败的 [test-ramfs-page-lifetime.py](../../hackios-xnu-kernel/tools/tests/test-ramfs-page-lifetime.py) 经实测已在当前 HEAD 通过。
- 用户已确认搁置两项：天气、备忘录、股票组件因无定位或 FairPlay 限制只显示占位骨架；打开「设置」时的半屏黑窗（[G18](../backlog/graphics.md)）在 542 格式修复后未再复现。
- 本地 `out/cam-frame/kroot` 与已登记的 `12377-cam*` 探针内核基于旧源码，按 `ANNFS001` 挂载 `/private/var`，无法在已转 APFS 的测试机上启动；后续相机探针须在内核 `4d570f48` 的独立克隆树上重新构建。
