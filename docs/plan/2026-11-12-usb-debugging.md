# 原生 USB 与调试工具核查（2026-11-12）

本批继续[渲染与运行时工作](2026-11-12-rendering-runtime.md)，按用户追加要求核查原生 USB 和便于调试的事项。用户允许对影响无人值守的 USB 接管暂缓实施；性能、渲染正确性和基础功能仍为后续优先方向。

上游与本仓核查已完成，原生 USB 接管暂缓。`fetch.py`、`health.py` 与 `loader-sample-series.py` 的修复和宿主验证见[本批结果](../analysis/2026-11-12-usb-debugging.md)。

## 1. 范围与交付

| 工作 | 交付 | 当前边界 |
|---|---|---|
| 上游原生 USB | 核对 UniXNU／Pagani 固定版本源码、依赖与实测范围 | 核对 SM8750 硬件参数及 23G90 ABI，暂不接管设备控制器 |
| loader 归属与恢复 | 确认 CPU、固件协议、端点、DMA 和中断的归属，列出接管影响 | 保留现有 `getvar`、`oem stop`、日志及 reboot 通道 |
| 当前调试工具 | 复现离线解析、返回值或诊断缺陷，实施可独立验证的最小修复 | 宿主模拟验证，不改变设备起轮与恢复状态机 |
| 网络调试参考 | 核对已有 SSH 构建与启动入口及当前产物 | 不自动启动服务，不读取密钥内容；设备连通性待独立验证 |

上游成员核查 QcomDwc3 与 Pagani，系统成员分析 loader 归属与恢复，工具成员复现主机诊断问题，主任务整合本仓构建依赖、结论、测试与提交。原始材料保存在 Git 忽略目录；公开结论写入分析文档，未完成项更新[外设待办 S8](../backlog/platform.md)及[工程待办](../backlog/engineering.md)。
